- (constraint) From brief: agent runtime is Claude Code for v1; distinct custom skills per job type (design, coding, review), not one general agent.
- (constraint) From brief: target environment is GitHub-hosted repos with CI pipelines; v1 trigger is a manually started pipeline; input is a user story .md file already in the repo.

- (constraint) From brief: single human role (the requesting developer) holds all three gates -- plan confirmation, evidence review, approval/merge. Evidence gate surfaces metrics plus a drillable PR/diff.
- (constraint) From brief: v1 scope ends at merge; staging deploy and controlled production rollout are explicitly deferred past v1.

- (decision) Repo shape for v1: blueprint/template copied into each target project's own repo (not a dedicated orchestrating repo). Factory logic (orchestration graph, agent skill configs, pipeline scripts) must stay isolated from GitHub-Actions-specific wiring so it can migrate to a dedicated cross-repo orchestrator later without a rewrite.
- (decision) Paradigm: hybrid state machine. GitHub Actions native Environment + required-reviewers protection rule owns the two long human-wait gates (plan confirmation, evidence review) as job boundaries -- GitHub pauses/resumes the same run natively, up to 30 days, zero extra infra. LangGraph owns the in-job agent orchestration graph (clarification loop, bounded fix loop, agent routing) within a single job's lifetime, so it never needs to survive across separate ephemeral runner instances.
- (decision) Rejected for v1: Camunda/Zeebe (BPMN engine) and Temporal -- both require hosting a separate stateful orchestration server, contradicting blueprint/minimal-footprint PoC goal. Deferred as the natural evolution if/when the factory becomes a dedicated repo orchestrating many target projects at scale; Temporal specifically fits durable cross-repo orchestration.
