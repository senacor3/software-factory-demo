- (constraint) From brief: agent runtime is Claude Code for v1; distinct custom skills per job type (design, coding, review), not one general agent.
- (constraint) From brief: target environment is GitHub-hosted repos with CI pipelines; v1 trigger is a manually started pipeline; input is a user story .md file already in the repo.
- (constraint) From brief: implementation runs in an isolated branch/workspace; deterministic checks (build/test/lint/security) run as direct pipeline steps, never delegated to an agent; review-fix loop is bounded (e.g. cap 2 cycles).
- (constraint) From brief: every agent invocation runs with least-privilege permissions scoped to its job (review agent read-only, implementation agent write scoped to its branch/workspace, no agent holds merge rights).
- (constraint) From brief: single human role (the requesting developer) holds all three gates -- plan confirmation, evidence review, approval/merge. Evidence gate surfaces metrics plus a drillable PR/diff.
- (constraint) From brief: v1 scope ends at merge; staging deploy and controlled production rollout are explicitly deferred past v1.
- (question) From brief, explicitly left open for this architecture phase: whether light-factory ships as a dedicated repo or as a blueprint/template integrated into a new or existing project. This is a primary decision for this run, not inherited.
- (decision) Repo shape for v1: blueprint/template copied into each target project's own repo (not a dedicated orchestrating repo). Factory logic (orchestration graph, agent skill configs, pipeline scripts) must stay isolated from GitHub-Actions-specific wiring so it can migrate to a dedicated cross-repo orchestrator later without a rewrite.
- (decision) Paradigm: hybrid state machine. GitHub Actions native Environment + required-reviewers protection rule owns the two long human-wait gates (plan confirmation, evidence review) as job boundaries -- GitHub pauses/resumes the same run natively, up to 30 days, zero extra infra. LangGraph owns the in-job agent orchestration graph (clarification loop, bounded fix loop, agent routing) within a single job's lifetime, so it never needs to survive across separate ephemeral runner instances.
- (decision) Rejected for v1: Camunda/Zeebe (BPMN engine) and Temporal -- both require hosting a separate stateful orchestration server, contradicting blueprint/minimal-footprint PoC goal. Deferred as the natural evolution if/when the factory becomes a dedicated repo orchestrating many target projects at scale; Temporal specifically fits durable cross-repo orchestration.
- (version) LangGraph (Python) verified current on PyPI 2026-10-01: v1.2.12, stable 1.x line, ~400M+ downloads. Human-in-the-loop via interrupt() + checkpointer + Command(resume=...). Source: https://docs.langchain.com/oss/python/langgraph/interrupts
- (version) GitHub Actions Environment protection rules (required reviewers) verified current 2026-10-01: pauses a running job in place pending 1-6 designated reviewers, resumes the same run on approval, wait timer up to 43200 minutes (30 days). Source: https://oneuptime.com/blog/post/2026-01-25-github-actions-environment-protection-rules/view
- (decision) Every stage ending in a human gate must emit a concise human-readable summary alongside the full detail file (e.g. plan.md gets a plan written as a PR/commit comment summarizing it; review.md gets a review summary), so the human can decide quickly whether to drill into full detail. Applies to both gates (plan confirmation, evidence review).
- (decision) Least-privilege agent permissions are enforced at two independent layers (defense in depth), neither sufficient alone: (1) Claude Code tool-allowlist per invocation -- e.g. review agent has no write/edit tool available at all; implementation agent's edit tools are scoped to its isolated branch checkout; no agent invocation has merge/admin tools. (2) Platform-level GitHub token/branch-protection scoping -- each job's token permissions block (contents/pull-requests/etc scopes) matches only what that job's stage needs, and branch protection rules prevent direct push to main / require PR + checks for merge, independent of what any agent attempts.
- (decision) Orchestration language: Python (LangGraph's native SDK).
- (decision) External dependencies for v1: GitHub (repo, Actions, Environments) and Anthropic/Claude Code only -- no ticket system or chat integration in scope.
- (decision) State directory layout: .light-factory/<story-slug>/ per story (plan.md, decisions.md, review.md, evidence), so concurrent stories don't collide.
- (decision) Claude Code auth: CLAUDE_CODE_OAUTH_TOKEN (subscription-based, Pro/Max/Team/Enterprise) instead of ANTHROPIC_API_KEY (pay-per-token). Billing draws from the subscription's shared usage budget rather than a dedicated metered account -- the bounded-fix-loop cost guardrail applies here too. Verified 2026-10-01, source: https://code.claude.com/docs/en/authentication
- (decision) Stage summaries post as PR comments (reuses the pattern already specified for the evidence gate); full detail stays in the committed .light-factory/ files for drill-down.
- (decision) Each pipeline stage writes only its own state file (e.g. the analysis stage writes plan.md and decisions.md, the review stage writes review.md) and never mutates a prior stage's file -- append-only ownership per file, preserving the audit trail. State files carry YAML frontmatter with a machine-readable status field so both the human reviewer and the orchestration script read the same source of truth.
