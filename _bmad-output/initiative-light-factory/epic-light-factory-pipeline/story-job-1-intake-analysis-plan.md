## Intent

**Problem:** Job 1 currently only stubs an echo step. CAP-1/CAP-2 need a real analysis stage: judge whether the triggering story is complete/in-scope, and if so propose a solution with subtasks and tests, writing `plan.md`/`decisions.md` through entry 2's `state_io.py`. (Entry 4, not this ticket, adds the clarification-loop round counter and cap-out path around this.)

**Approach:** Add a read-only `.claude/skills/light-factory-analysis/` skill (judges completeness/scope, proposes a solution, derives subtasks/tests, lists open questions — all in one structured-JSON response) and `factory/graph/analysis_graph.py` (a minimal LangGraph graph: one node shells out to `claude -p "/light-factory-analysis ..." --output-format json --json-schema <schema> --allowedTools "Read Grep Glob"`, parses `structured_output`, and routes to one of three outcomes — incomplete/out-of-scope halts with no file written; complete with no open questions writes `plan.md`+`decisions.md` via `state_io.py` with `status: ready-for-review`; complete with open questions writes both with `status: awaiting-clarification`, carrying the questions for entry 4's loop to pick up). Wire the workflow's `analysis` job to invoke it after the existing slug/run-id derivation step, replacing the stub echo.

**Decision:** CAP-1's "complete"/"in-scope" judgment is loose and agent-driven — no required template or sections; the skill prompt asks only "is this clear enough to design a solution, and does it belong in this codebase's scope?" — user's call, 2026-10-01.

**Decision:** implement the full workflow-wiring now (not split into a separate ticket), but defer the live dispatch itself: `CLAUDE_CODE_OAUTH_TOKEN` is not yet a repo secret, the user will provide it later, and live verification happens then — user's call, 2026-10-01. (Superseded by the live verification recorded in `## Verification` below, 2026-10-02.)

**Approach (amended 2026-10-02, `change-pr-at-intake`):** once `run_analysis` returns a non-halted result (not `AnalysisHalted`), a new deterministic step — before the function returns — creates the isolated branch (`light-factory/<story-slug>/<run-id>`), commits the just-written `plan.md`/`decisions.md` as the branch's real first commit, and opens a PR against the target branch (AD-12, moved from Job 2 per the `change-pr-at-intake` sprint change proposal; no placeholder commit needed — the plan docs are genuine content). On `AnalysisHalted`, behavior is unchanged: no branch, no commit, no PR. The workflow's `analysis` job gains `contents: write`/`pull-requests: write` permissions it has none of today.

**Decision:** branch+PR creation (originally entry 6's scope, "Deterministic PR-open step") is absorbed into this ticket per the `change-pr-at-intake` sprint change proposal — approved 2026-10-02. AD-15's supersession-closing (search for and close a prior open PR for the same story-slug on retrigger) is explicitly **not** part of this amendment — deferred separately, see `deferred-work.md` — since no currently-built or in-flight ticket exercises an actual retrigger path yet.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Complete, in-scope, no open questions | Story file judged complete by the skill, `open_questions: []` | `plan.md` + `decisions.md` written via `state_io.py`, `status: ready-for-review`; branch `light-factory/<story-slug>/<run-id>` created, both files committed as its first commit, PR opened against the target branch | n/a |
| Complete, open questions remain | Skill returns `complete: true`, non-empty `open_questions` | `plan.md` + `decisions.md` written, `status: awaiting-clarification`, questions carried in the body; branch/PR created same as above | n/a — entry 4 consumes this |
| Incomplete or out-of-scope | Skill returns `complete: false` or `in_scope: false` with a `reason` | Run halts with the reason printed; no `plan.md`/`decisions.md` written; **no branch, no commit, no PR created** | Graph exits non-zero with the reason on stderr |
| Claude CLI invocation fails (non-zero exit, malformed JSON) | `subprocess` call errors or `--json-schema` validation fails | Graph halts loudly, no partial state file written; no branch/PR created | Distinguish from a legitimate "incomplete" verdict — this is a tooling failure, not an intake judgment |
| Branch/PR-open step itself fails (`git`/`gh` subprocess error) | `run_analysis` already decided to proceed and wrote `plan.md`/`decisions.md` locally, but the deterministic script's `git`/`gh` call errors | Graph halts loudly with the `git`/`gh` error surfaced; distinguish from both the "incomplete" and "CLI invocation fails" cases — the analysis succeeded, only the PR-open step failed | Raise a distinct exception type so the three failure modes never get confused in logs |

**Acceptance Criteria (amendment, 2026-10-02):**

- Given `open_pr_for_story` is called twice for the same story-slug/run-id (idempotent-reuse case), when the branch/PR already exists, then it returns the existing PR's info rather than erroring or duplicating.
- Given the `git`/`gh` subprocess call itself fails after a successful non-halted analysis, when `run_analysis` runs, then it raises `AnalysisPROpenError`, distinguishable from `AnalysisHalted` and `AnalysisInvocationError`.

## Design Notes

**CLI invocation shape** (verified against current official docs, not training-data recall): `claude -p "/light-factory-analysis <story-file-path>" --output-format json --json-schema '<schema>' --allowedTools "Read Grep Glob" --permission-prompts none`, run from the repo root (so the skill auto-discovers) with `CLAUDE_CODE_OAUTH_TOKEN` already in the environment. Do **not** use `--bare` — it skips skill auto-discovery entirely and requires `ANTHROPIC_API_KEY` instead of the OAuth token, which would silently violate AD-9. The response JSON's `structured_output` field holds the schema-validated payload; `result` holds the raw final text (log it, don't parse it). Skill invocation is by literal `/skill-name` text in the prompt — there is no separate CLI flag for it; this is the same convention this repo's own bmad skills already use.

**Why the graph writes state, not the agent:** giving the analysis invocation zero write/edit tools is stricter than per-path `Edit` scoping and sidesteps trusting the CLI's path-scoping syntax under adversarial story-file content. It also directly mirrors AD-12's already-adopted precedent (a deterministic script opens the PR, not the agent) rather than introducing a second permission model for this ticket alone.

**Why entry 4 isn't duplicated here:** the ticket's own `verify` text names exactly two tested outcomes (ready-for-review happy path, halt-on-incomplete) and the epic's breakdown lists "Bounded clarification loop" as a separate, later entry (`after: [3]`) covering CAP-2's loop/cap half. This ticket still has to produce the `awaiting-clarification` state (otherwise entry 4 has nothing to loop on), but the retry/cap/cap-out-comment logic itself is out of scope here.
